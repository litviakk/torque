# tf engine — registry sync from Terraform

Terraform-backed service registry sync. Populates registry.edn from infrastructure-as-code: Terraform state → inventory → registry.edn.

`src/clj/torque/registry/tf_engine.clj` (Phase 1+)

## Sync Lifecycle

Registry is the generated snapshot from IaC. The sync pipeline:

1. **Define** in Terraform (services, backends, environment definitions)
2. **Generate inventory** via `bb inventory:generate` (extracts from TF outputs + local `bb.edn` config)
3. **Sync to registry** via `bb torque registry sync` (TF engine writes registry.edn from inventory template)
4. **Commit** to git (registry.edn is now the snapshot)
5. **All modules read** from the committed snapshot (nool, deploy, etc.)

## Phase 1 (Alpha): Minimal TF Sync

Phase 1 includes the full registry sync pipeline from Terraform with **service `:mlflow` only**:

```
Terraform (mlflow service defined)
    ↓
bb inventory:generate (extract from TF outputs + bb.edn)
    ↓
bb torque registry sync (TF engine writes registry.edn)
    ↓
registry.edn (committed to git)
    ↓
all modules read from committed snapshot
```

This is sufficient to prove the sync works end-to-end with nool and dial. Additional services (keycloak, zot, openbao) added in Phase 2.

## Drift Management (OQ-F)

`registry.edn` is both generated (from TF via sync) and committed to git. It can drift from actual infra state if sync is not run.

**Policy (Phase 0–1):** Manual sync only.
- Developers run `bb torque registry sync` before deploying
- Commit the updated registry.edn
- No runtime validation or automatic sync
- Documentation: "Always run registry sync and commit before deploying"

**Future (Phase 2+):** CI could validate registry freshness on PR. Runtime startup checks deferred.

## TF Engine API

```clojure
(registry/sync!)             ; extract from TF inventory + state, write registry.edn
```

The engine:
- Loads `inventory.yml` (generated by `bb inventory:generate` from Terraform state/outputs)
- Reads local `bb.edn` environment config
- Validates service data
- Writes `src/clj/torque/registry.edn`
- Throws `ex-info` with fix hint on validation error

## Open Questions

**OQ-E: Terraform output gap (Phase 1)** — Service FQDNs (mlflow, zot, nginx) are not Terraform outputs today. How should `registry sync` derive them?

Options:
1. Convention: `<service>.dev.balkan.coffee` (hardcoded domain per environment)
2. Add TF outputs for each service FQDN to `applications/org/outputs.tf`
3. Hardcode defaults in sync template; allow per-environment override

**Decision needed before Phase 1 multi-service implementation.**

## Source of Truth

- **Terraform**: Service definitions, image sources, environment config
- **bb.edn**: Local environment config, bootstrap values
- **Registry module**: Owns sync, validation, schema
- **registry.edn**: Generated snapshot (committed to git)

All other modules read from registry; never write directly.
